# Text animation as engine-state orchestration, not a sixth Layer

## Status

**Canon.**

Supers introduces a new domain — `textAnimations` — that binds a curated catalog (24 effects vendored from `pixel-point/animate-text` plus GFX-authored additions) to text slots in a preset. The domain is modeled as a flat `textAnimations: TextAnimation[]` array on `EngineState`, peer to `marks.timings`, with each entry carrying a discriminated `target`, an `effect` id, an `enter` window, and an optional `exit` window in the standard `TransitionSchema` shape. At runtime a single `TextAnimationManager` resolves each entry's target DOM node via a `data-text-anim-slot` attribute on the slot's CanvasSource, splits the text via GSAP SplitText, and feeds `AnimationTweenSpec[]` produced by `src/lib/text-animations/compile.ts` into the existing `AnimationManager` so every text-animation tween scrubs by `progress = time / durationSeconds` alongside surface enter / exit, overlay enter / exit, and per-mark timings.

Compiler dispatches on the effect's `renderer` field across four strategy modules: `generic-stagger` (covers ordinary per-effect `from` / `to` keyframe endpoints and `duration_ms` / `stagger_ms` from the catalog) plus three layout-aware adapters — `kinetic-center-build`, `kinetic-top-build`, `shared-slide-opacity-stage` — that follow each effect's `recipe.canonical_loop_pseudocode` and `recipe.keyframe_recipe` from the vendored JSON. The catalog ships as ~480 KB of Zod-validated JSON in `src/lib/text-animations/raw-catalog/`, pinned to a specific upstream SHA and resynced via `scripts/sync-text-animation-catalog.ts`. Per-character effects are parse-time restricted to title-scale slots (`surface.content.title`, `kicker`, `lower-third.title`); a GFX-authored effect may also declare `title_scale_only` when its per-word or whole-unit behavior belongs only at display scale. Layout-aware renderers remain title-scale-only because they reflow the line itself.

Body marks ride along with their unit's animated alpha: the marks renderer reads per-unit alpha from `TextAnimationManager.unitAlphaAt(slot, unitIndex)` per frame and multiplies into the drawn mark alpha, so a body that carries both `marks.timings[]` and a `textAnimations[]` entry stays visually correct without authoring constraints. Playback is single-pass enter plus optional exit per entry; the source skill's wall-clock loop is intentionally not adopted because Supers forbids wall-clock playback. The accepted verification Preset was `text-anim-showcase-generic`; its completed Brief was deleted under ADR-0007's delete-on-ACCEPT policy.

## Considered options

- **A sixth Layer (`TextAnimation`) peer to Surface / Block / Annotation / Overlay / Effect** (rejected: text animations do not render — they choreograph the DOM that HTML-in-Canvas captures into the WebGPU composite. The five-Layer grammar in `docs/CONTEXT.md` is about _rendered Layers_ with their own Pipeline / Registry membership, and adding text animations there would force per-effect-ID Pipeline files (24 files) for what is really one compiler reading 24 JSON configs. The grammar stays at five Layers; text animation is a peer to `marks.timings`, not to `annotations[]`).
- **Inline `*Animation` field per text slot** (rejected: `SurfaceContent` already carries `string | undefined` slots for `title`, `kicker`, `sourceUrl`, `author`, `source`, `dateLabel`, `affiliation`, `bodyLabel`, and would gain a sibling `titleAnimation`, `kickerAnimation`, etc. for every animatable slot. Bloats every CanvasSource, every overlay content schema, and the preset shape itself. The flat `textAnimations[]` array mirrors how `marks.timings[]` already orchestrates per-target timed motion against body segments — same pattern, same place in the schema).
- **Per-effect Pipeline registration (24 files in `src/lib/pipelines/text-animations/`)** (rejected: 21 of 24 effects are generic-stagger variants that differ only in their `from` / `to` keyframe endpoints, `duration_ms`, `stagger_ms`, and `easing` — all read from the catalog JSON. One compiler serves them. The three layout-aware renderers each have a unique algorithm that warrants its own strategy file but not its own Pipeline registry slot. Per-effect Pipelines would create 24 thin shells that all delegate to one of four strategies).
- **Hand-rolled splitter under `src/lib/utils/text-split.ts`** (rejected: GSAP SplitText handles unicode combining marks, emoji clusters, and RTL out of the box; ships free with GSAP since the 2024 Webflow acquisition; integrates cleanly with the existing GSAP timeline that `AnimationManager` already owns. Hand-rolled would re-solve those edge cases and add a maintenance surface for a problem that's already solved upstream. The Brief notes that swapping to a hand-rolled splitter behind the same `TextAnimationManager` interface remains a one-file contained change if SplitText turns out to be unavailable in the installed package).
- **Catalog as git submodule** (rejected: pinning to a specific upstream sha via vendored JSON gives identical reproducibility with no CI / clone-time submodule friction. The catalog is ~480 KB of stable JSON, not a live dependency; vendoring is the simpler model. `scripts/sync-text-animation-catalog.ts` handles the resync when upstream ships new effects).
- **Catalog fetched at build time from upstream** (rejected: defeats offline determinism, makes CI builds depend on GitHub availability, and gives no diff visibility into upstream changes. Vendored JSON shows every schema drift as a normal code review).
- **Catalog as an npm package consumed at runtime** (rejected: not under our control — pixel-point would need to publish it. Vendoring lets us ship today without that dependency).
- **Adopt the skill's wall-clock loop (enter → hold → exit → micro-delay → gap, repeating)** (rejected: violates the binding rule in `CLAUDE.md` "Frame-determinism: Drive all animation from an explicit timestamp / frame value. Scrub paused GSAP timelines by progress; never play by wall-clock." Preview and export must produce identical pixels at the same time. The compiler bakes each entry's `enter` + optional `exit` into a finite timeline that fits the user-declared window; runtime loop playback is not in v1).
- **Strict isolation: body cannot have both `marks.timings[]` and `textAnimations[]`** (rejected: research-paper-style presets are the dominant Supers use case, and they both mark up the body AND want a `fade-through` or similar transition motion on the body. Mutual exclusion forces an authoring constraint that defeats the point of having both systems. The ride-along integration is ~20 LOC in the marks renderer and produces visually correct results across every overlap case).
- **Untreated coexistence: marks draw at full alpha during a body fade** (rejected: a highlight stripe visible at full intensity above text that is still fading in is visually wrong on every overlap case. The 30% of the fade where the body is at ~0.3 alpha and the mark is at 1.0 alpha reads as a broken render, not a deliberate motion).
- **Multi-phrase swap in v1** (rejected for v1: full skill fidelity requires slot content to become `string | { static, phrases[] }`, plus a deterministic cycle function across phrases. Real schema delta and real visual surface; deserves its own Brief. The four phrase-swap effects (`fade-through`, `shared-axis-x/y/z`, `per-word-crossfade` when used as a transition) still work in v1 as one-phrase enter / exit reveals — they don't disappear from the catalog, just lose their swap behavior. Multi-phrase lands as a follow-up Brief).
- **Per-character animation on body in v1** (rejected for v1: per-character on paragraph-scale text reads as noise, not motion. The slot rule restricts per-character to title / kicker / lower-third.title at parse time. A future Brief may unlock per-character on short body passages or pullquote-shaped bodies once a reading-friendly design exists).
- **Canvas-side glyph rendering instead of DOM** (rejected: would require building a parallel text-shaping pipeline in TypeGPU — kerning, baselines, font loading, line breaking — which is multi-week scope. HTML-in-Canvas already captures DOM into the WebGPU composite for every existing text slot; reusing that path keeps the surgery contained. The DOM-level path also means existing CanvasSources only need a `data-text-anim-slot` attribute added — no rewrites).

## Consequences

`EngineState` gains one new field — `textAnimations: TextAnimation[]` defaulted to `[]` — and existing presets remain valid without modification.

## Amendment (motion-primitives plan, Phase 3.3) — catalog vs Pipeline rule, sharpened

The original ADR scoped catalog membership by renderer-family fit ("falls under the four existing renderer algorithms") but did not pin the _structural_ test for when a new motion verb is catalog-shaped versus Pipeline-shaped. The motion-primitives plan exposed two boundary cases that need a rule sharper than "feels catalog-y" — `kerning-pop` (letter-spacing animation on a title slot), `bracket-pop` (overshoot on `[](){}<>0-9` glyphs only), and the negative example "ink-blot reveal" (per-glyph mask that bleeds ink into the glyph shape). We pin the boundary as a two-clause AND: a motion verb belongs in the catalog if and only if (a) it is expressible as **per-unit** keyframed motion — per-character, per-word, or per-line — with no inter-unit pixel dependencies; AND (b) every keyframe endpoint is **CSS-rasterizable** without a custom shader pass — meaning the unit's appearance at each keyframe can be produced by CSS properties (transform, opacity, letter-spacing, color, filter from the standard list) that HTML-in-Canvas captures into the composition texture without a per-unit fragment program. Both clauses must hold; either failing kicks the verb to a Pipeline. `kerning-pop` passes both: it animates `letter-spacing` per-character (clause a), and the rendered letter at every progress is a normal CSS-shaped glyph (clause b) — catalog. `bracket-pop` passes both: it overshoots `transform: scale` on a glyph subset (clause a), and the rendered glyph at every progress is the same glyph with a different transform (clause b) — catalog. The selector-by-character-class is part of the catalog effect's `target.matchClass` field; the catalog compiler walks the SplitText output and applies the keyframes only to matching characters, no new renderer family needed. Hypothetical "ink-blot reveal" fails clause (b): a per-glyph mask that bleeds ink into the glyph shape requires a fragment-shader-evaluated mask field (a 2D noise function with seeded brush physics) that no CSS property produces and HTML-in-Canvas cannot capture from DOM — it has to run as a shader pass on the per-glyph rasterized output. That makes it a Block-class Pipeline (with its own Identity Spec claiming a `motion-form` dimension via the brush-physics mask), not a catalog entry. The rule rejects what the original ADR's anti-pattern list called "Pipeline-shaped motion smuggled through the catalog lane" — the catalog lane is not a back door for shader-class effects to ship without an Identity Spec, and the two-clause test names the exact structural difference. `kerning-pop` and `bracket-pop` ship as Phase 4.1 catalog entries under this amendment. The `textAnimations[]` array is the second flat per-target timed-motion list on `EngineState`, joining `marks.timings[]`; the pattern is now established and future timed-motion domains (audio cues, camera moves) would land the same way unless a stronger reason emerges. The 5-Layer grammar is unchanged; `docs/CONTEXT.md` gains new glossary entries (**TextAnimation**, **Effect (text)**, **Split mode**, **Renderer family**) but the Layer count, the Pipeline Registry shape, and the per-Layer effect-chain composition are all untouched. The Critic continues to verify Presets without ever seeing the Brief or this ADR; the four showcase Presets (`text-anim-showcase-generic` + three per-renderer-family showcases) are the visual verification surface, and the complete catalog compile-time unit-snapshot suite is the regression surface. `src/lib/text-animations/` becomes a new module sibling to `src/lib/platform/` and `src/lib/annotations/`; it is the only home for text-animation code and the only consumer of the vendored catalog. New text-animation effects ship to Supers as data refreshes (re-running `scripts/sync-text-animation-catalog.ts`) rather than code changes, so long as they fall under the four existing renderer algorithms; effects with new renderer algorithms require a new strategy file under `src/lib/text-animations/strategies/`. The marks renderer becomes the only existing module that reads from `TextAnimationManager`; the coupling is one-way (marks read text-anim state, text-anim never reads marks) and gated on the body slot having an entry, so when `textAnimations[]` is empty the marks path is a no-op identical to today. The Control Panel grows a "Text Motion" section and per-slot Motion pickers, mirroring how the marks system has both a body editor (where marks are created) and a `marks.timings[]` panel (where they are tuned); the timeline rail gains text-animation tracks alongside existing tracks. GSAP SplitText is added to the runtime dependency surface; if a future GSAP packaging change removes SplitText from the free distribution, the swap to a hand-rolled splitter is contained inside `TextAnimationManager`. Multi-phrase swap and per-character animation on body remain outside this slot-bound domain; first-class phrase choreography belongs to the Type Field designed by ADR-0063.

## Amendment (2026-09-15) — normalized variable weight is a catalog endpoint

`weight-resolve` is the third GFX-authored Effect (text) and the first endpoint that addresses a real OpenType axis. It still passes the two-clause catalog rule: SplitText units are independent, and HTML-in-Canvas captures `font-variation-settings` on normal DOM glyphs without a shader. Its keyframes use `font_weight_normalized` in `[0,1]`, where `0` maps to the active Pack's minimum, `0.5` to its art-directed rest, and `1` to its maximum. The Pack supplies a distinct self-hosted variable face through `variable-weight-treatment`; existing static faces stay in place for every text run that does not select this effect, so adding the substrate cannot re-key ordinary corpus pixels. The manager resolves the treatment when it materializes each unit, and the frame writer refreshes it from inherited Pack variables so a live Pack swap cannot leave the old face or coordinates inline. It applies both `font-weight` and `font-variation-settings: "wght" …` with `font-synthesis: none`. Each word's inline box is locked to its settled weight geometry while the glyph outline remains free to interpolate; this prevents a light, loosely tracked entry frame from snapping a word onto another line. A missing treatment or a target whose Identity blocks Pack appearance makes the effect unavailable; the engine never substitutes `scaleX`, fake bold, or a static-cut staircase. `weight-resolve` stays title-scale-only even though it splits per word. The `text-anim-variable-weight` fixture and `pnpm probe:text-animation-weight` are the deterministic Pack × orientation proof. This is a reusable substrate for ADR-0063's Kinetic Word tracks, not the multi-phrase model itself.
