# ADR-0052 — Host the public demo on a Node/ffmpeg origin with zero content retention

## Status

**Canon (ratified from live probes; the runtime it decides is built and verified on a local production-shaped origin).** **Amended 2026-08-31:** public deployment is descoped. GFX is local-first — the production image is built and served on loopback under the same `public` runtime profile, and there is no public origin. The `gfx.computer` zone is reserved for a future docs site (Dex `kb6d6wyb`), not for this app. Nothing below is retracted: every runtime, limit, retention, security, and header decision still governs the artifact, and the profile they are enforced under is still `public`. What changed is only who can reach it. The body is preserved as ratified on 2026-08-28, so read its future-tense framing as the decision's own context rather than as current status.

**Amended 2026-09-02: a hosted origin, with the browser as the encoder.** gfx.computer now serves the app from one Cloudflare Worker under a third runtime profile, `hosted`, declared by the presence of `PUBLIC_GFX_HOSTED` — the one input the page and the origin both read. The Worker serves the app shell, the Workspace, and the static build, and encodes nothing: the browser renders _and_ encodes every export itself through the Mediabunny VP9 lane in `browser-webm-export.ts`, the lane the ffmpeg transport replaced in July 2026 for alpha quality, now measured by `pnpm verify:hosted-export` rather than assumed. What that origin cannot do is stated by the same inventories that govern the Node origin: the export transport is a `node-origin` surface (`public-surface-inventory.ts`) and answers 404 there like every development-only route; ProRes 4444 is not offered (`composition-export-formats.ts`), because it is an ffmpeg lane; the disk-backed authoring the GUI could only reach a 404 with is hidden; `/api/health` answers `not-served` for the encoder and the disk it has no need of. The one header change the lane needed is `worker-src 'self' blob:` on the Content Security Policy: Mediabunny splits a transparent piece's colour and alpha in a worker built from a Blob URL, and without the directive a transparent export failed while an opaque one passed — which `pnpm verify:hosted-export` is what caught. The lane is lossy VP9 where the Node lane is lossless, so it is held to its own ratified tolerances (`BROWSER_EXPORT_DECODE_TOLERANCES`), measured against the frame the browser presented at the same address rather than against an assumed clear border: on the lower-third deliverable the decoded frames drift 1.78 levels of colour and 0.0065 of alpha, with a border residue of at most 4 levels where the source border is exactly clear; on the chapter-card deliverable 2.10 levels of colour with no alpha at all. A 7-second 4K piece exports in about 15 seconds. The evidence is [`../runtime-probes/hosted-export.json`](../runtime-probes/hosted-export.json). The Node-origin decisions below — the export envelope, the session security binding, temp-disk retention, the container image — keep governing the local production artifact and are simply not exercised by a host that has no encoder. The retention promise is stronger there, not weaker: a Worker with no volume cannot keep a frame. Deployment inputs are held by `findHostedRuntimeDeploymentFailures`: a release identity and the browser-scoped store, and nothing else. The Cloudflare rule narrows rather than reverses: the Worker holds no KV, D1, R2, or Durable Object, no library or architecture is chosen for edge compatibility, and the one Node-only package the server tree imports (Playwright, behind the development-only site-capture route) resolves to a stand-in in the hosted build (`vite.config.ts`). Rendering in a visitor's unflagged Chrome rests on the HTML-in-Canvas origin trial, registered to this origin and sent as the `Origin-Trial` header from `GFX_ORIGIN_TRIAL_TOKEN`; the trial's end (Chrome 154 as extended, or a stable ship) is the one external clock this origin runs on. The apex was serving the docs site (`docs-site/`, Worker `supers-docs`) at the time of this amendment; the app takes `gfx.computer` and the docs site moves to `docs.gfx.computer`, declared in its own `wrangler.jsonc`. Operational steps, including that hand-over, are in [`../hosted-origin-runbook.md`](../hosted-origin-runbook.md).

**Amended 2026-10-08: the `development` profile has its own export limits.** A local checkout renders Films ([ADR-0068](0068-films-scenes-and-live-scene-boundaries.md) §9), so a `development` host admits `DEVELOPMENT_EXPORT_RUNTIME_LIMITS` instead of the public envelope: 600 seconds and 120 fps (the composition schema's own transport ceilings), 72,000 frames, 64 MiB per frame, 64 MiB of audio, a 128 GiB output ceiling, 2 concurrent sessions, and a 15-minute idle expiry inside a 24-hour hard lifetime. `exportRuntimeLimitsForProfile` (`public-runtime-deployment.ts`) is the one place a profile becomes an envelope, and `ExportSessionStore` reads it from the environment it starts in. The `public` and `hosted` profiles keep every number ratified below: the production image still refuses a 901-frame session, and the hosted origin's browser lane now refuses an export outside the public envelope before it renders a frame, in the Node lane's own words, because it has no session admission to do it for it. Three things follow. The audio ceiling equals the frame ceiling because the bed is one request and both share the adapter's `BODY_SIZE_LIMIT`, so a development host carries about 349 seconds of 16-bit 48 kHz stereo and no more until the bed is uploaded in parts. `/api/health` keeps the public 8 GiB temp-disk reserve on every profile: the development worst case is 256 GiB, and holding a local machine's health to that would report nearly every one unavailable for a reserve a real Film never approaches. And a page cannot read its origin's profile, so `GET /api/export/limits` serves the limits the store enforces with `Cache-Control: no-store`; `gfx_capability_inspect_limits` reports those to an agent, and reports the public envelope where the route is absent, which is the hosted origin. Refusal messages say "the limit is" rather than "the public limit is", since the same sentence is now spoken by a host that is not public. The probe evidence under `docs/runtime-probes/` and `docs/browser-probes/` recorded before this date keeps the earlier wording.

**Amended 2026-10-09: the docs site serves no `llms.txt` manifest.** Scott ruled this out on 2026-08-31, when an agent proposed it; it is recorded here late. docs.gfx.computer publishes no `llms.txt` and no `llms-full.txt`. His reason: a manifest has proven ineffective where the docs site itself can be navigated. So the site's answer for an agent reader is the one it gives a person: every published page is reachable from the navigation and listed in the prerendered `search.json`. Do not add a manifest route to `docs-site/`. The published set is still decided by one list, `PUBLISHED` in `docs-site/src/lib/server/docs.ts`.

## Context

gfx.computer is going live as a public, no-account authoring demo. Everything about that demo except the runtime has been decided: the browser lane is measured, the WebMCP transport is specified, and the composition model is unchanged. What was still assumed rather than proven was the host.

The repository carried a Workers-shaped build (`@sveltejs/adapter-cloudflare`, `wrangler.jsonc`, generated worker types) that no server route could actually run on. Export is not an edge workload: a session spawns ffmpeg, streams native-resolution PNG frames into its stdin, writes the encoded file to private temp disk, and streams that file back once. Three live probes settled it:

- `wrangler deploy --dry-run` on the Workers build failed with 57 unresolved Node built-in imports, including `node:child_process`, `node:fs`, and `node:os`. The reproducible half of that measurement — the built-ins the server modules import — is recorded as `serverNodeBuiltins` in the probe evidence.
- The same tree built with `@sveltejs/adapter-node` produced a Node server that serves the whole demo, including both export lanes, from one process.
- The Node adapter's 512 KB `BODY_SIZE_LIMIT` default rejects every native-target frame upload with `413`. The public host must raise it; nothing in the code can compensate for it.

Measured cost, from `pnpm probe:public-runtime` against the built Node artifact with distinct high-entropy 3840×2160 frames (the worst case; real compositions compress far better):

| Lane                               | Output per native frame | Encode wall clock (8 frames) | Decoded                         |
| ---------------------------------- | ----------------------: | ---------------------------: | ------------------------------- |
| ProRes 4444 + PCM audio + timecode |             1,669,843 B |                       883 ms | `prores` 3840×2160, `pcm_s16le` |
| VP9 lossless, transparent          |               444,437 B |                     2,712 ms | `vp9` 3840×2160                 |

Cancellation released the encoder and its work directory in 6 ms; two concurrent sessions completed in 3.1 s wall clock; every terminal path left zero work directories and zero encoder processes.

## Decision

**One long-lived Node process, ffmpeg on the same host, private per-session temp disk, and no durable content of any kind.**

**Runtime.** SvelteKit builds through `@sveltejs/adapter-node`. The public artifact is a single Node server plus an ffmpeg binary exposing `libvpx-vp9`, `libopus`, `prores_ks`, and `pcm_s16le`. There is no second tier, no queue, and no render worker; the browser renders frames and the origin encodes them.

**The image pins its versions in one place, and proves them.** `Dockerfile` builds that artifact: a Node base image pinned by digest, pnpm and ffmpeg pinned by exact version, and nothing else deciding what the host is made of. The build fails rather than drifts — it reads `REQUIRED_FFMPEG_ENCODERS` out of this contract and refuses an ffmpeg that cannot encode a public lane, and it refuses to build at all without the `GFX_RELEASE` of the commit it serves, because there is no checkout inside the image for `/api/health` to fall back to. The resolved versions are written to `/app/runtime-versions.json` so a running container can be asked what it is. The server runs as the unprivileged `node` user, export work directories live on a declared volume at `/var/lib/gfx/export` rather than the container's writable layer, and the container healthcheck reads the same `/api/health` a rollback does.

No fonts are installed. The origin never rasterizes text — it reads PNG frames the browser already rendered and pipes them into ffmpeg — so every typeface the demo uses is a web font served out of `build/client`. Node runs as PID 1 without an init shim for the same kind of reason: the adapter installs its own `SIGTERM` and `SIGINT` handlers, and every ffmpeg the host spawns is its direct child.

**A misconfigured public host never listens.** `GFX_RUNTIME_PROFILE` says what a host is being asked to be. `development` is every local checkout and adds no requirements, so the dev server and `vite preview` are untouched. `public` — which the image sets — is held to `public-runtime-deployment.ts`: `ORIGIN`, a `BODY_SIZE_LIMIT` of at least `maxFrameBytes`, an absolute `GFX_EXPORT_TEMPORARY_DIRECTORY`, a `GFX_RELEASE`, a concurrency no larger than the temp-disk reservation covers, and the browser-scoped composition store. The check runs in the server `init` hook, which the Node adapter awaits before it listens, and names every unusable input at once with the value that would fit — so one restart fixes a whole deployment, and a host that cannot finish an export never accepts one. Readiness stays separate and non-fatal: a host whose ffmpeg or temp disk is momentarily unusable answers `/api/health` with 503 rather than crash-looping.

**Cloudflare is DNS and proxy only.** No Workers, KV, D1, R2, Durable Objects, or Cloudflare-hosted state. `App.Platform` is gone: request handlers use Node APIs directly. This does not change how the engine is developed — local development stays local-only, and no library or architecture choice is ever made "for Cloudflare compatibility."

**Deployment inputs are one inventory.** `PUBLIC_RUNTIME_DEPLOYMENT_INPUTS` in `src/lib/platform/public-runtime-contract.ts` names every environment input the host reads, who owns it (this app or the adapter), and what it is for. `parsePublicRuntimeConfig` validates the app-owned ones and throws a corrective error on a malformed value, so a misconfigured host fails at startup rather than mid-export. `ORIGIN` and `BODY_SIZE_LIMIT` are required of a public host; `BODY_SIZE_LIMIT` must be at least `maxFrameBytes`.

**Limits are ratified here and enforced before any expensive work.** `PUBLIC_EXPORT_RUNTIME_LIMITS` fixes the public envelope: 15 seconds, 60 fps, 900 frames, 64 MiB per frame, 8 MiB of audio, a 2 GiB output ceiling, 2 concurrent sessions, a 15-minute idle expiry inside a 30-minute hard lifetime, and 8 GiB of free temp disk before the host admits traffic. The output ceiling is derived from the measured per-frame cost above with headroom (`RATIFIED_NATIVE_OUTPUT_BYTES_PER_FRAME`), and `public-runtime-contract.test.ts` keeps the numbers mutually consistent.

`public-export-limits.ts` decides whether one request, upload, or open session fits, and names the bound it missed with the value that would have fit. `ExportSessionStore.create` applies the transport ceiling, the envelope, and the concurrency slot in that order — before it spawns ffmpeg, and before it creates a work directory — claiming the slot in the same tick it checks so two callers cannot both win the last one. Duration is measured from the exact frame-rate rational, so 900 frames at 59.94 is refused as 15.015 seconds. Rate, frame count, and duration answer `400`; byte ceilings (per-frame, session total, audio, projected and actual output) answer `413`; a saturated host answers `429` with its running count; a session past either clock is removed and answers `410`. Frame pixel dimensions are deliberately not checked: the envelope is sized so only native-target work fits, but the transport still accepts whatever the client rendered, so the reduced-size verification sweeps keep using the same lane.

**Temp disk is private and per session.** Each session gets its own directory under the configured temp parent. Only the encoded output and, when present, the audio bed are ever written; frames stream into ffmpeg's stdin and are never stored. The directory is removed on completion, on failure, on cancellation, on idle expiry, and after the download drains — and a startup sweep removes anything a terminated process left behind.

**Every disposal is receipted, and never throws.** `public-export-cleanup.ts` names why a session ended and records what it actually released: the download body, the encoder process, and the work directory. A disposal that falls short is logged and asserted rather than assumed, and the request that happened to end the session still gets its own answer instead of the cleanup's. The order is what makes a removal a removal — an unlinked file that is still open keeps its blocks, so an in-flight download is closed first, then the encoder is killed, then the directory goes. That is also how the hard lifetime ends a transfer that never drains.

The orphan sweep runs at startup and then on the idle-timeout cadence, skipping directories a live session still owns: a directory the replaced process left seconds before the restart is too young for the startup sweep, and nothing else would come back for it. "At startup" is the `init` hook, not module scope — SvelteKit imports a route module the first time a request matches it, so a sweep hanging off the export module would run at the first export rather than at boot, and a host that never got one would inherit the previous process's directories forever.

The sweep, not a shutdown hook, is the retention guarantee: a host that is killed outright never runs one, and its encoders reach EOF on the stdin pipe it took with them. A host that is _signalled_ still releases its open sessions, because that is a different question — an in-flight encode has no visitor left to hand output to, and an ffmpeg child outliving the HTTP server would hold the process open past the orchestrator's grace period and turn a graceful stop into a kill. So `sveltekit:shutdown`, which the adapter emits once in-flight requests have drained or been cut off at `SHUTDOWN_TIMEOUT`, disposes every open session under its own `shutdown` cleanup reason and receipts it like any other terminal path.

**Downloads are single-shot and uncached.** The output response sends `Cache-Control: no-store` with an exact `Content-Length`, `X-Content-Type-Options: nosniff`, `Vary: Cookie`, and `Accept-Ranges: none`, and it ignores a `Range` header; the session and its file are destroyed as the body finishes. A second request for the same output is a 404. Resumable downloads would require retaining rendered content, so they stay out of scope; the client re-exports instead. The response carries no `Content-Disposition`: the browser names the file from the `download` attribute the app sets, which is where the [ADR-0042](0042-resolve-marker-sync.md) sync filename comes from, and a server-supplied name would silently override it.

**What comes out is verified by decoding it, not by trusting the encoder.** `public-export-decode-contract.ts` states what a decoded export must contain, and `pnpm verify:export-decode:public-matrix` measures a live export of every lane against it — both formats, transparent and opaque, with and without an audio bed, at both native target sizes. Neither format reports its output class in a container field, so the class is read off decoded alpha rather than a `pix_fmt` string: ProRes is always encoded 4444 and decodes as `yuva444p12le` whether the piece is transparent or not, and VP9 carries alpha as WebM `BlockAdditional` side data, which only the libvpx decoder reads — so a transparent WebM correctly reports a plain `yuv420p` stream, while the opaque lane is `yuv444p` because it has no separate alpha to keep full-rate. Cadence is checked against the exact frame-rate rational rather than a decimal literal, within the millisecond the Matroska timecode scale quantizes to. Every decoded frame is then matched back to the frame that was uploaded, nearest-source first, so a reordered or duplicated sequence fails even when each frame on its own is clean.

**An export session belongs to the browser that opened it.** There are no accounts, so `public-export-security.ts` binds a session to its opener with two unpredictable 258-bit identities: the session identity, which names the session in URLs and therefore in logs, and a private credential, which the create response sets as an `HttpOnly; SameSite=Strict` cookie scoped to that session's own path and to its hard lifetime. Every later request — upload, completion, cancellation, and the download — is authorized against that credential, so the download is authorization rather than a link anyone holding the URL can follow, and one visitor's session can never read another's output.

`ExportSessionStore` decides in a fixed order, so the transport never answers a question it was not asked: a caller from another origin is refused before anything is looked up, a session identity the origin did not issue is refused before it can name a file, and a caller presenting no credential never learns whether the session exists. A mutating request must carry an `Origin` matching the request URL — which the Node adapter resolves from `ORIGIN`, never from `Host` or an `X-Forwarded-*` header — and a download navigation, which carries no `Origin`, must be `Sec-Fetch-Site: same-origin` or `none`. A frame body is held to exactly the length it declared in both directions, so a caller can neither understate a frame to slip past the per-frame ceiling nor have a body that stopped short encoded as a torn frame. The open sessions are never listable: the collection endpoint accepts `POST` only.

**Diagnostics are redacted before they are logged, not after.** A failed encode answers a fixed `Export encoding failed.`; ffmpeg's own output names the private work directory it was writing to, so it is logged at the origin with the session's work directory, identity, and credential removed, along with any other absolute path — the same rule the telemetry attributes already follow.

**Observability is redacted by construction.** The export lane may emit only the keys in `PUBLIC_EXPORT_TELEMETRY_ATTRIBUTE_KEYS` — format, rate, frame count, audio bytes, opacity, whether a timecode was supplied, encode milliseconds, output bytes. No composition content, filenames, paths, or session identities. `/api/health` reports liveness and release identity only: no paths, versions, or capacity.

The request log follows the same rule rather than a second one. `public-error-observability.ts` decides what a host may say about a request it answered with an error: a development host keeps the query string and the raw body, because it is the machine that also has the checkout; a public host keeps the status, the method, and the path, drops the query string entirely, and puts the body through the redaction above before it is logged or promoted to Sentry. Redacting is not the same as saying nothing — a public 5xx still carries the message it answered with.

**Every public response carries the same headers, and a development host carries none of them.** `public-response-headers.ts` is that set: HSTS, `nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy` of `same-origin`, `Origin-Agent-Cluster`, a Content Security Policy on every document, and `Cache-Control: no-store` unless the response already declared its own caching. The Permissions Policy grants `tools=(self)` — the WebMCP surface [ADR-0054](0054-webmcp-operation-transaction-and-security-contract.md) §7 registers only in gfx.computer's own top-level document — plus `autoplay` and `fullscreen`, and denies nineteen powerful features by name so a dependency that starts asking for one is refused rather than prompting a visitor on our behalf.

Two absences are deliberate. `X-Frame-Options` is not sent, because `frame-ancestors 'none'` says the same thing to every browser that has shipped in a decade and two spellings of one rule drift. `Cross-Origin-Embedder-Policy` is not sent, because cross-origin isolation buys `SharedArrayBuffer`, which the measured render lane does not use, and `require-corp` would break cross-origin subresources for no gain.

The policy is composed at request time rather than built in, because the profile decides it and the profile is a runtime input. SvelteKit owns the nonce on the app shell's inline bootstrap script, so `kit.csp` declares `script-src` and the hook merges what SvelteKit emitted into the full policy — a CSP is enforced as a whole, so a second header would only intersect with the first and drop that nonce. `https://analytics.tolin.ski` is the one external script and connection origin admitted for page-view analytics; it receives no composition content. `style-src` carries `'unsafe-inline'` on purpose: the engine positions and animates every composition element through inline `style` attributes, and there is no hash or nonce form for an attribute that changes every frame. `blob:` is allowed as an image, as media, and over `fetch`, because a visitor's own media never reaches the origin — it is read from a granted file handle into an object URL. The header layer covers every response the SvelteKit handler produces; `build/client` is served by the Node adapter's own static handler ahead of the hook and keeps that handler's immutable caching, which is the adapter's lane and has no configuration seam.

**No durable content.** The public runtime persists nothing on behalf of a visitor: no accounts, no server-side composition store, no uploaded media, no output archive.

The routes that would break that promise are excluded by name. `public-surface-inventory.ts` classifies every server surface as `public` or `development-only` and the server hook answers 404 for the second kind before the route module runs — so an excluded surface never reads a body, touches disk, or spawns a browser. Development-only means one of four things: it keeps durable visitor content (the User composition, asset, and poster stores), it reads the repository (`/api/backdrops`, `/api/verification/…`), it answers a control-plane question about our own tooling (`/api/sentry-canary`), or it makes the origin fetch an address an untrusted caller chose (`/api/website-capture`, `/api/x-post` — the rule ADR-0054 §7 states). The `/poc/` proof-of-concept routes are engine scratch space and go with them. A 404 rather than a 403: publicly the surface does not exist, and "forbidden" would confirm that this deployment has one.

Content follows the same line where a public route would otherwise carry it. The homepage lists deliverable Presets only — fixtures document an engine gap rather than ship ([ADR-0039](0039-pack-neutral-compositions-and-listing-hygiene.md)) — and reports no poster keys, because the public runtime has no disk-backed poster store to read; each library card carries the URL of its committed poster instead, a still that ships with the app ([ADR-0061](0061-committed-composition-posters.md)). `/p/<fixture-slug>` resolves to nothing there, so an unlisted slug is not a back door into a listing decision.

**Rollback is verified against the origin.** `/api/health` reports the release the process is serving, from `GFX_RELEASE` or the checkout commit. A deploy or rollback is confirmed by reading that value back from the public origin rather than by trusting the deploy tool. Because sessions are in-memory and content is never durable, rolling back loses only in-flight exports.

## Consequences

- `wrangler.jsonc`, `worker-configuration.d.ts`, the `wrangler` and `@sveltejs/adapter-cloudflare` dependencies, and the `gen` script are gone. `pnpm build` now emits `build/index.js`.
- `pnpm verify:production-image` is the third gate, and `docs/runtime-probes/production-image.json` is its evidence. It builds the image, re-executes the pinned runtime layer and requires the rebuild to land on the same versions, withdraws each required deployment input in turn and requires the container to exit without listening, then drives the running container: readiness against the built release, nonroot execution, the export volume's ownership and mount, the encoders, the app shell and its web fonts, the public response headers and a Content Security Policy that still carries the app shell's bootstrap nonce, a 404 from every development-only surface, one export per format decoded back to what was uploaded and downloadable exactly once, and a `docker stop` that exits 0 having released the session that was still open. It needs a container runtime and a local `ffmpeg`/`ffprobe`, so it is a command a person runs rather than part of `pnpm check`.

- The exclusion check probes a real route behind every development-only prefix, because a subtree answers 404 for a path that does not exist either. Adding a prefix row without naming a route behind it fails the gate rather than passing it vacuously.
- The adapter's output is not self-contained: its server chunks import the production dependencies by name, so the image carries `node_modules` for the production tree rather than `build/` alone.
- Pinning ffmpeg to an exact Debian version means a security update to that package makes the build fail rather than silently move. That is the intended failure: the pin is bumped deliberately in the `Dockerfile`, and the encoder assertion re-runs against the new binary.
- The image still carries `playwright`, which only `/api/website-capture` uses. Its browsers are not downloaded, so it costs disk rather than capability; excluding the developer surfaces themselves is a separate change under this epic.
- A signalled host's shutdown is bounded by `SHUTDOWN_TIMEOUT` (10 seconds in the image), so an orchestrator's stop grace has to exceed it or the drain becomes a kill.
- The host is stateful in memory: sessions live in one process, so it cannot be scaled horizontally without a session-affinity decision that this ADR does not make.
- Concurrency is deliberately small. Two native-resolution encodes already saturate a modest host, and the temp-disk reservation is sized for exactly that.
- ProRes remains available publicly despite costing about 1.7 MB per native frame; a full-length export is roughly 1.5 GB, which the output ceiling and the temp reservation both account for.
- Any client of the export transport must present the session credential and its origin. A browser does both on its own; `scripts/probe-public-runtime.ts` echoes the `Set-Cookie` value itself, because Node's `fetch` keeps no cookie jar.
- `pnpm probe:public-runtime` is the regression gate for this ADR. It fails when a lane exceeds its ratified per-frame cost, when a download becomes cacheable or partial, when output survives its download, or when any terminal path retains a directory or an encoder process. It drives each terminal path repeatedly against the real encoder — a drained download, a cancellation, a refused frame, and an encode ffmpeg cannot complete — because a fixture's stand-in for a process cannot prove a process died.
- `pnpm verify:export-decode:public-matrix` is the second gate, and `docs/runtime-probes/public-export-decode-matrix.json` is its evidence. It fails when a lane decodes at the wrong size, codec, chroma layout, or output class; when a frame is dropped, duplicated, or reordered; when a decoded frame drifts past its lane's tolerance; when a saturated host, an abandoned upload, a cancelled session, or a closed download leaves a work directory or an encoder behind; or when a refused bound answers without naming the value that would have fit. `PUBLIC_EXPORT_DECODE_TOLERANCES` is set just above the drift measured here (1.544 levels of colour and 0.040 of alpha at worst, both on the 4:2:0 WebM lane); the ProRes lane is byte-identical across repeated exports of the same frames, and every abandonment path released its session, encoder, and directory within 162 ms.
- Aborting a streamed frame upload has to be measured from the origin's own state, not the client's. A streamed request is queued in the client before it is flushed, so a probe that aborts as soon as its body stalls can destroy the request before the origin has seen a byte, and then reads an untouched session as a leak. The origin marks a session busy for exactly as long as it is reading a frame, and that is the signal the probe aborts on.
- One bound is unreachable from the create path and is deliberately not probed there: at the ratified per-frame cost, 900 frames of ProRes project below the 2 GiB output ceiling, so `frameCount` always binds first. `outputBytes` is enforced on the encoded result instead, and `public-export-limits.test.ts` covers it directly.
- **The 2026-08-31 descope leaves the artifact intact and removes only its audience.** `GFX_RUNTIME_PROFILE=public` is now a profile a local host runs, not a claim that a host is reachable from the internet. Every gate keeps its meaning under that reading: the deployment-input check, the exclusion of development-only surfaces, the export envelope, the security binding, and the response headers are all measured against a loopback origin by [`../production-serve-rollback-runbook.md`](../production-serve-rollback-runbook.md). Rollback is still confirmed by reading `/api/health` back — from that origin rather than from a public one, which is also why the release identity is a commit rather than a URL's self-report ([`../release-acceptance.md`](../release-acceptance.md)).
- Cloudflare's role shrinks to holding the `gfx.computer` zone for a future docs site. The rule the DNS/proxy-only decision exists to protect is unchanged and still binding: no Workers, KV, D1, R2, or Durable Objects, and no library or architecture chosen for edge compatibility. A statically hosted docs site on that zone does not reopen it, because it serves no app request.
